# 指摘判断の更新結果が不明な場合の確認

Issue #105。main `c91788b`、390px、Mock/専用DBで解決済み・見送り・未対応の実PATCH200後にbrowser応答だけを失わせた。DBは希望状態、表示は旧状態、通常再送可能、操作後の詳細GET0だった。3状態が同じReviewPanel.changeStatusの通信結果契約を共有している。

Finding単位のPATCHの通信・5xx・成功応答の読取/構造/指摘ID・runID・希望状態の不一致を結果不明として判断操作を停止する。既知4xxの安全な拒否メッセージと再試行は保つ。更新時のdocument/workspace/run/revision/finding/希望状態と指摘文章を固定する。人間が本文を新しい版へ保存したり、別のレビュー履歴を表示しても、明示GETで元の指摘の現在状態を読む。自動PATCHやレビューPOSTをしない。

GETは対象run/document/revisionと一意なfinding/statusを検証する。失敗・欠落・対象不一致では不明のまま。成功したGETは該当する表示中のrun/指摘だけを現在状態へ更新する。別レビューの表示や本文/名前/資料/関連の入力を更新しない。別画面の判断や遅れて反映される元のPATCHがあり得るので、GET成功・希望状態との一致だけでは元要求の完了と見なさない。明示のリスク承認が新しい判断を有効にし、承認自体はPATCHしない。

scope/mount/attempt identityと同期pending/reading refで二重操作と旧訪問のPATCH/GET success/error/finallyを無効にする。受付不明と指摘更新不明は独立して保持し、どちらか一方の承認で他方の保護を解除しない。指摘更新不明もノートの移動/beforeunload保護へ加える。
