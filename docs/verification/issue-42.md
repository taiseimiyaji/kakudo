# Issue #42 — 資料操作の状態・エラー・再試行

## 実装と受け入れ条件

- 資料一覧の初回読込中、空一覧、読込失敗を区別。失敗時は「資料を再読み込み」から再試行する。
- 取得確認・関連解除は資料行単位、関連付け・登録はフォーム単位で処理中を表示。disabledと同期的なrefロックで二重送信を防止する。
- 成功・失敗は対象行または操作フォーム内で日本語表示。共通Feedbackのstatus / alertとaria-atomicで読み上げに伝える。解除成功は消えた行の代わりに関連付けフォームで資料名を含めて通知する。
- URL・タイトル・種類の検証エラーをaria-invalid / aria-describedbyで入力欄へ関連付け、最初のエラーへフォーカスする。通信失敗時は入力と選択を保持する。
- 取得失敗はUNAVAILABLEとし、「内容が間違っているという意味ではありません」と明示。サーバーのレスポンス本文・内部例外を利用者へ出さず、共通APIクライアントで日本語の案内へ変換する。
- Node / Document / Workspaceの切替時はパネルの状態を分離する。SSRF・DNS rebinding・redirect再検証・timeout・size limit・sanitize処理は変更していない。

## 共通UI依存（#39）

実装開始時点で#39は未完了であり、利用できる共通部品がmainに存在しなかった。このPRで必要最小限のFeedback部品と入力エラーの関連付けパターンを先行導入し、資料・マップ・Node詳細・レビューの操作エラーで共用する。#39全体のテーマ整理・日本語ラベル管理・レスポンシブ改善は完了扱いにしない。後続の#39はこの共通部品を土台として利用できる。
