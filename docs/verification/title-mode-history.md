# 閲覧／編集で名前のUndoを保持する（Issue #148）

## 再現と変更

main `4e499baf5a80860142b39baea9b9f897cff55b1a`、Chromium 390/1440px、通常時計・native keyboard・Mock・隔離DB・一時Markdownで再現した。名前を入力してUndo/Redoすると切替前は実際の入力単位に戻るが、閲覧→編集後はUndoが無反応になる。名前のtextareaがmode条件で作り直されるため、選択も失われる。本文DOMと保存済みデータは不変だった。新規回帰2件も修正前に同じUndo期待値で失敗した。

名前のlabel/textareaを同じDocumentSession内で保持し、閲覧中はhiddenにする。既存のlabel表示CSSに勝つ局所ルールで非表示にし、読取用h2は維持する。編集再開は従来どおり本文focus。保存・自動保存・CAS・引用・関連・別ノートのsession identityは変更しない。ブラウザーのnative Undoを使い、独自または永続のUndo機構は追加しない。

## 検証

- 新規4件成功（17.7秒）。390/1440pxの通常時計で、同じ名前/本文DOM、名前の選択、native Undo/Redo、通常自動保存を確認。切替のみは書き込み0、名前変更後も本文Hash・Revision・確定関連は不変。
- 閲覧時は名前欄が非表示で、role検索とChromium CDPの公開AXツリーから除外される。native Tabを8回移動しても名前欄へfocusしない。編集再開は本文focus。
- 制御した既知400で自動保存を止め、モード往復と名前Undoでも失敗状態・未保存入力を保持する。明示再試行は元のbaseを使い、その後のRedoは成功した保存の新しいbaseで保存する。本文・登録済み引用・人間の目標は同じMockレビューのRevisionに残る。
- 実SPAで一覧→別ノート→一覧→元ノートへ移動し、新しい名前DOMと空のnative履歴を確認。移動・新しい欄のUndoは書き込み0で、両ノートの保存済み全文・名前・baseは不変。
- 既存のタイトル幅/文字拡大、IME契約、本文の選択/Undo、引用待機/Undoなど15件も成功した。最終の全体チェックはPRに記録する。

初回の新規Tabチェックは、修正前の閲覧時に名前欄が存在しないため、そのlocator評価でtimeoutした。実際のactiveElementを評価する形へ訂正し、修正前2件のUndo失敗を記録した。修正後の保存失敗ケースでは、停止時計のUI pollが完了を再取得できずレビュー表示の期待値に失敗した。実サーバーのMock完了を待ってからpoll時計を進める形へ訂正した。保存境界の期待値を弱めず、新規4件が成功。初回traceも保存している。

## 範囲と限界

同じ開いているノートのモード往復だけを対象とする。別ノートへの移動、再訪、reload、クラッシュ後に履歴を復元しない。通常保存の2件と別ノートの1件は通常時計、既知失敗の1件は制御時計を使う。初期本文・名前・関連・引用はAPI fixture、その後の入力と操作は実UI。ChromiumのAX公開情報を確認したが、Safari・実Mac IME・VoiceOverなど実支援技術は未検証。実ユーザーDB・実AI通信・実資料取得・認証・本番・#128・保留PR135は変更していない。
