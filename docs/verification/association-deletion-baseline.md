# 関連項目・マップ削除後の保存済み基準

Issue #99。main `078f0ad`、390px、Mock、専用隔離DBで、保存済みの二つの項目のうち一つを別画面から削除し、元のノートで候補を再取得する操作を確認した。項目削除とその親マップ削除の双方で、表示されたチェック一つとサーバーの関連ID一つが一致しているのに未保存表示と移動警告が出た。ノートと人間の本文は保持されていた。

DocumentNodes が有効な候補から削除された選択を取り除くとき、dirty の保存済み基準も、成功した完全な候補一覧に存在する関連項目だけで比較する。これは既に表示する linked 項目と同じ基準である。候補の GET が失敗した場合は既存の候補・選択を維持し、削除を推測しない。

人間が別の有効な項目をチェック/解除していれば、保存済みの有効な関連との差分が残るため、未保存表示と移動保護を継続する。再取得は読み取りのみで、関連 PATCH・本文書き込みはしない。関連を保存するときは人間の残っている有効な選択を確定する。

`tests/e2e/association-deletion.spec.ts` は、項目/マップ削除と、人間の未保存選択の有無を組み合わせた390pxの4ケース。本文を人間が追記し保存→二つのマップの項目を関連付け→Mock学習目標レビュー→別画面から削除→候補再取得→移動まで検証する。修正前は、実際の変更なしの二経路が未保存表示の残留で失敗し、実際の未保存選択を持つ二経路は成功した。

未保存選択を持つケースは候補GETの503と再取得も検証し、残る人間の選択、移動警告、明示的な関連保存、本文不変を確認する。候補再取得に伴う自動PATCHがないことも送信回数で検証する。

候補一覧は既存の workspace 内の全項目を返すAPIを使用する。別画面で有効な項目同士の関連だけが変更された場合の照合は、この削除確認の変更とは別の既存契約である。本文・ノート名の保存契約、AI、認証、デプロイは変更しない。
