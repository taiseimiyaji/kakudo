# 保存再開前の読み取り専用比較（Issue #146）

## 目的と範囲

main `8c073cd62b906e06ecc2694fbcdf3bd22a1d178d` での復帰・履歴移動監査では不具合はなかった。これは、長いノートで現在の入力と取得した保存内容を離れた位置で見比べる手間を減らす、ユーザー承認済みの表示改善。

明示的に「最新の保存内容を確認」で取得した後、「現在の入力と比べる」を開閉できる。現在の名前・Markdown本文と、取得時の保存済み名前・Markdown本文を並べる。関連はこの画面の確定済み情報と取得時の保存済み情報を比較し、未保存のチェック選択は含めない。「関連を保存」で別に確定することを明記する。

`NoteSaveComparison` は渡された情報の表示と開閉状態だけを持つ。保存、競合検知、基準承諾、結果不明の確認、明示再試行の処理は既存のものを使用する。AIによる生成・自動マージはない。

## 実UIの検証

公式ブラウザrunner、隔離PostgreSQL、終了時に消去する一時Markdown、Mockで追加3ケースを確認した。長文の初期本文・登録済み引用・関連はAPI fixtureで用意し、本文の追記・選択・Undo・比較・保存再試行は実UIを操作する。ブラウザ時計は制御して自動保存のタイミングを固定している。

- Chromium 390/1440 CSS px：長文と登録済み引用のMarkdown原文を全文一致で確認。390では縦、1440では横に並び、横にはみ出さない。Tab、Enter、Space、PageDownで操作し、本文表示をスクロールできる。
- 比較の開閉でGET/PUT/POST/PATCHが増えず、現在の名前・本文・編集器identity・選択範囲・native Undoを保持する。入力を続けると現在側の表示も更新する。
- 未保存の関連Bを比較の確定済み関連に混ぜない。比較後の再試行は旧hash/writeIdのまま実409になる。明示基準承諾だけでは書き込まず、その後の本文再試行は取得済みhash/writeIdを使用し、Bや引用POSTを送らない。
- 結果不明の503を制御して注入。GET失敗時と取得結果を遅延させている間は比較を表示しない。遅延中の追加入力・名前を保持し、取得時点の本文を表示する。取得後に別の実保存が入れば、基準承諾後の再試行も実409で保護する。再取得・承諾・明示再試行後だけ全文と名前が保存される。
- 結果不明の既存説明と確認Dialogを維持。確認の拒否で再試行は無効のまま、承諾だけでも書き込まない。

初回3件はテスト側の想定で失敗した。GETエラーはサーバーの注入文言ではなく既存の正規化された読取エラーを表示する。停止時計下でEnd直後のスクロール位置を断定する代わりに、PageDownと実スクロール位置のpollで確認した。製品処理は変更せず、修正後の追加3件は成功（5.9秒）。失敗traceと成功画面をローカル証跡に保存。必須チェック全体の最終結果はPRに記録する。

## 限界

Chromiumのみ。Safari、実Mac IME、支援技術、全履歴イベント、クラッシュ後の復元は未検証。最新保存は取得時点のスナップショットであり、その後の更新は既存CASで保護する。引用本文の比較だけでは直前の引用操作の成功・失敗を確定しない。比較は行単位diffや永続下書きを提供しない。確定関連の表示は名前のみで、未保存選択や学習目標の編集は含めない。既存ユーザーデータ、実AI通信、実資料取得、認証、本番、#128の仕様判断は変更していない。
