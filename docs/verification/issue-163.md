# Issue #163: 復元後の保存説明を隠さない

## 実測した境界

main `1b69d7a`、390 CSS px、Mockと専用E2E DBで、端末下書きの初期OFF説明を読み、有効化して本文を編集した。保存PUTを503としてノート一覧から別ノートへ移動し、元のノートへ戻った。サーバー版と候補を比較し、候補を編集器へ復元した時点で、保存状態の説明「復元した入力はサーバーに未保存です」が候補ボタンの下に隠れた。文字範囲とボタンの矩形交差を確認し、修正前のアサーションは `Expected false / Received true` で失敗した。

## 修正

保存状態に注意が必要な間だけ、端末下書きへのジャンプボタンを通常のFlex配置に戻し、説明の後へ並べる。ボタンと説明の高さに応じて領域が伸びる。通常執筆のツールバーと本文開始位置は維持する。保存、端末候補、AI、権限、サーバーAPIの動作は変更しない。

最初の注意状態の案では、ボタンのために固定48pxを空けていた。390px・CSSズーム2倍の一時QAでボタンが118pxとなり、説明の文字範囲と12px交差したため、固定値を使わない配置に変えた。9つの幅（390/639/640/641/998/999/1000/1001/1440px）とCSSズーム1/1.5/2倍の計27条件では、修正後に文字範囲とボタンは交差せず、横スクロールも発生しなかった。

最初の全面的な並べ替え案は新しい一連テストを通したが、全ブラウザ回帰で390pxの本文開始位置1件と引用ダイアログのスクロール2件を失敗させたため採用しなかった。注意状態だけの配置に絞った後、この3件を含む対象13件は通過した。

## 検証

- 新しい実ブラウザの一連操作を390pxと1440pxで実行。初期OFF説明、有効化、失敗後の内部移動、別ノートに候補なし、再訪時の比較、編集／閲覧両モードの保存説明とボタンの非交差、復元後の追記、明示保存前のPUT試行なし、保存後の本文、再移動を確認した。両幅のスクリーンショットも目視した。
- 390px・CSSズーム2倍で、ボタンが48pxを超えても説明と交差しないこと、横スクロールなし、候補ボタンのクリックで候補へ移動すること、検索ボタンからTabで候補ボタンへ到達しEnterで候補へ移動することを確認した。
- lint、typecheck、build、unit 311件、PostgreSQL 17 clientを指定した隔離DB integration 66件が成功。最初のintegration実行は `PG_BIN_DIR` を指定しておらず、backupテストで `pg_dump could not start` となった。既存clientを指定した再実行では全件成功した。
- サイズ追従案の全ブラウザ初回は336件成功・既存の復元Undo/Redo 1件失敗。失敗した1件は単独で成功し、ブラウザだけを再実行した全337件も成功した。初回失敗の確定原因は未特定。exact head CIの結果はPRで記録する。

Mock、隔離DB、一時Markdown、Chromiumでの確認。CSSズームはページ全体の一時的な拡大模擬であり、ブラウザUIのnative zoomや実支援技術の確認ではない。実ユーザーデータ、実AI、有料通信、本番配置、認証・権限設定は触れていない。
