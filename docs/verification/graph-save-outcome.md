# マップ・学習項目の保存結果の確認

Issue #109。main `f6c5307`で、マップ名／項目の学習目標を実PATCH200で保存した後、ブラウザ応答だけを失わせた。自動GETが保存内容を取得しても通常の失敗・再試行を表示し、別画面がその後変更した内容を普通の再試行で上書きできた。各経路で当画面PATCH2／別画面PATCH1を実測した。

対象は人間が明示するマップ／項目の保存フォーム。requestGraphSaveは送信値を既存schemaで正規化し、成功応答のschema・対象ID・マップ／workspace・全送信フィールドを検証する。通信、5xx、JSON・schema・対象・送信値不一致は結果不明とし、通常の保存を止める。既知4xxは安全な拒否と再試行・入力保持を維持する。同期pending refとフォームの同期guardで同時submitを止める。

回復は送信時のworkspace／マップ／項目／入力を固定し、明示GETでその対象の現在値を別欄に表示する。GETは編集フォーム、資料、次の項目名、選択、viewportを変更しない。同じ値／違う値のどちらも元要求の完了証明にしない。読取失敗・別scope・項目なしでは了承できない。mounted／scope／attempt identity／読取ref／refreshVersionで旧応答を除外する。再読取中は前の比較結果で了承できない。

読取後の明示了承は遅れた元要求や別画面変更の上書きリスクを説明し、通常の保存だけを再開する。GETと了承はPATCHしない。作成結果不明と保存結果不明のロックは独立。保存成功が確認された後の表示GET失敗は、保存確定・表示再取得という既存契約を維持する。結果不明も移動・beforeunloadの保護対象にする。
