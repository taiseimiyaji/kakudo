# 学習項目の作成結果と次の人間入力の保持

Issue #107。main `125a635`で、実POST201後のbrowser応答喪失→回復GET成功でも通常の再作成が可能で、POST2/同名項目2を実測した。同じ作成フォームで、実201の返答待ち中に入力した次の名前を成功時のform.resetが消すことも実測した。

既存requestCreationの通信/5xx/成功JSON・schema不明の扱いを項目POSTへ適用する。成功応答は項目ID・対象マップ・送信したtrim後の名前を検証する。既知4xxは従来の安全な拒否と入力保持。同期pending refで連続submitを止める。成功時は送信した名前のままの入力だけを消し、待機中に変わった人間の次の名前は保持する。新規入力はcontrolled stateとし、入力/結果不明を移動・beforeunload保護へ追加する。

既存CreationRecoveryに学習項目を追加し、workspace/マップをscopeとして送信名を固定する。回復GETはそのマップのdetail/schema/id/workspaceを検証し、同名の候補を確認する。scope/mounted/read refとrefreshVersionで古い訪問・重複GET・新しいrefreshより前の読取を排除する。候補GETはgraphを更新しても選択を変更せず、map/node/edgeのdraftは既存reconcileで人間の編集を保持する。viewportのReactFlowを作り直さない。候補なし/複数/別画面の同名も同じ要求の完了と見なさず、候補の閲覧やgraph選択でも不明ロックを残す。

重複リスクの明示了承後のみ新規作成を可能にする。GET・了承でPOSTはしない。確定作成後の表示GET失敗は既存actの「保存済み・表示再取得失敗」契約を維持し、作成不明と混同しない。サーバーAPI、接続/削除/既存項目PATCH、マップ/ノート作成の要求契約・通常表示は変更しない。
