# Issue #40: マップ編集の未保存入力保護

実施日: 2026-09-21

## 受け入れ条件と実装

- マップ名・説明、Node名・説明・状態・学習目標・問い・X/Y座標をcontrolled formで保持し、保存値との差分から未保存状態を表示する。
- 別Node選択はNodeの未保存変更について確認する。マップ側の入力は保持される。画面移動・別マップ・履歴移動はTanStack Routerのblockerで確認し、再読み込みにはbeforeunloadを使う。文言はノートと同じ「未保存の変更を破棄して移動しますか？」。再読み込みのダイアログ文言はブラウザ標準。
- Node移動・接続操作・資料関連付けなどの再取得でフォームを再マウントしない。編集したフィールドは保持し、未編集フィールドは最新データを反映する。Node追加時も編集中のNode選択を維持する。再取得レスポンスの順序逆転で古いデータが上書きされることを防ぐ。
- 各フォームに保存中／保存成功／失敗と再試行の案内を表示。操作中は編集を無効化し、保存・再取得が完了してからdraftを解放する。失敗時は入力を残す。
- 同一内容の保存とサーバーでの正規化後も未保存警告を解除。意図的な削除は削除確認に集約する。Node削除で別のマップ編集は破棄しない。
- 自動保存・AI生成・本文補完は追加しない。#39は未完了のため、既存フォーム／status／alertの表示方法を継続する。

追加browser testでは、複数フォームの同時編集、項目切替キャンセル／破棄、画面移動／別マップのキャンセル、履歴移動、再読み込みキャンセル、Node drag、資料関連付け、Node／マップ保存失敗と再試行、保存中表示と入力無効化、同一内容保存、タイトル正規化、保存後の再表示、未保存状態での削除を確認。

## 初回失敗と再検証

- Integration初回は`pg_dump`の実行パス未設定でbackup testが失敗。`PG_BIN_DIR`設定後の共有テストDBでの実行はreview受付上限に関する2件が失敗した。新規のIssue専用DBでは全39件通過。
- Browser初回は修正前buildを使用していた一覧画面のnull参照と、キャンセルしたreloadのテスト待機で失敗。nullガードを含む再buildと、reloadキャンセルの待機上限設定後に全件通過。
