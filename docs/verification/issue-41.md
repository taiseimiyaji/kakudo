# Issue #41: マップ更新後の編集位置を保持する

2026-09-21。#40 / PR #44 のフォーム保持方針（編集フィールドだけ保持し、未編集値は取得結果に追従）を取り込み、離脱確認・保存状態表示を維持した。
#39の共通UI整理は未完了のため、既存の色・フォーム・ボタン・レスポンシブのルールを利用する。追加する表示ラベルは日本語とし、別のデザイン体系は導入しない。

## 受け入れ条件

- MapCanvasのkeyから更新番号を除去。同じマップではReact Flowを再マウントせず、Node / Edgeの取得結果を反映する。Nodeの計測値、Edgeの選択、接続フォームの選択を保持する。資料取得中にドラッグしている場合は操作中の位置を優先する。
- 初回と別マップへの移動で全体表示。同じマップ内の保存・移動・座標入力・接続追加・資料関連付けではviewportを保持する。「全体を表示」「拡大」「縮小」は明示的に操作できる。
- 選択中Nodeの詳細は#40の共通draftを利用。関係のない更新で未保存の目標や説明を失わない。PCでは詳細欄を独立してスクロールでき、マップ操作後もスクロール位置を維持。1000px以下は従来の下段配置を維持する。
- 保存失敗では最後の取得位置へ一度戻し、サーバーを再取得する。書き込み後に応答だけが失われた場合も確定済み座標に復帰。再取得も失敗した場合は最新状態を確認できない旨を表示する。
- 24項目のマップで拡大・パン後に3回の移動と接続追加を反復し、viewport、Node / Edge選択、未保存目標、詳細欄スクロールを検証。資料関連付け、座標入力の保存失敗・再試行、書き込み後の応答欠落、別マップ移動と履歴戻りも検証。
- 1440 / 1024 / 768 / 390px幅のスクリーンショットを生成して目視確認。PCの3カラムと詳細スクロール、狭幅の下段詳細、フォーム折り返し、横方向のページはみ出しがないことを確認。スクリーンショットはbrowser testの出力 `map-{width}.png` に再生成される。
